## Pamatojums

Kontaktpersonas ir fiziskas personas. Tāpēc VDAR prasības ir pašā prasību sarakstā un no tām izriet divi arhitektūras elementi: **administratora loma** un **piekļuves žurnāls**.

## Detalizētās prasības

### 1. Datu minimizācija

- N2.1 Kontaktpersonai glabā tikai: vārdu, amatu, darba e-pastu, darba tālruni, saziņas pamatu un tā datumu ([F2](F2.md)). Citu lauku datubāzē nav.
- N2.2 Formā — brīdinājums neievadīt personas kodu, adresi un privātas piezīmes.
- N2.3 Pirms teksta nodošanas MI modelim e-pasti un tālruņi tiek aizstāti ([MI-1](MI-1.md)).
- N2.4 Piekļuves žurnālā netiek glabātas personas datu vērtības — tikai objekta ID un darbība; labojot — tikai mainīto lauku nosaukumi.
- N2.5 Visi sākumdati ir sintētiski (`@piemers.lv`, izdomāti vārdi).

### 2. Glabāšanas termiņš

- N2.6 `retain_until` = pamata datums + **3 gadi**; tiek pārrēķināts, mainot pamata datumu.
- N2.7 Organizācijas kartītē kontaktam ar pagājušu termiņu — atzīme «Termiņš beidzies».
- N2.8 Administrators redz skaitu «N kontaktiem termiņš beidzies» un sarakstu (`/administresana?beigusies=1`), no kura var dzēst.
- N2.9 Automātiskas dzēšanas pēc termiņa nav — lēmumu pieņem administrators.

### 3. Piekļuves žurnāls (`piekluves_zurnals`: kas, ko, kad)

| Lauks | Saturs |
|---|---|
| `user_id` | Kas |
| `entity`, `entity_id` | Ko: `organizacija`, `kontakts` vai `lietotajs` + ID |
| `action` | Darbība (teksts) |
| `at` | Kad (UTC) |

| Notikums | Objekts | Darbība |
|---|---|---|
| Organizācijas kartītes atvēršana (redzami kontakti) | organizacija | skatīta kartīte (N kontakti) |
| Organizācijas izveide / labošana | organizacija | izveidota / mainīta |
| Mijiedarbības pievienošana | organizacija | pievienota mijiedarbība |
| Kontakta izveide | kontakts | izveidots |
| Kontakta labošanas formas atvēršana | kontakts | atvērta labošanai |
| Kontakta saglabāšana | kontakts | mainīts: `<lauki>` |
| Kontakta dzēšana | kontakts | dzēsts pēc pieprasījuma |
| Lomas maiņa | lietotajs | loma mainīta: `<no>` → `<uz>` |

- N2.10 Žurnāls redzams tikai administratoram: pēdējās 50 darbības, kolonnas Laiks (UTC), Kas, Ko (organizācijai — nosaukums; kontaktam — tikai ID), Darbība.

### 4. Dzēšana pēc pieprasījuma

- N2.11 Dzēst var **tikai administrators** (`POST /administresana/kontakti/<id>/dzest`); darbiniekam un vadītājam — 403.
- N2.12 Kontaktu atrod pēc vārda (`/administresana?q=`) vai termiņu sarakstā; rāda tikai vārdu, organizāciju un termiņu.
- N2.13 Dzēšanai obligāti jāatzīmē «Apstiprinu dzēšanu: <vārds>»; bez tā — paziņojums «Dzēšana nav apstiprināta — atzīmē apstiprinājuma lauku.», nekas netiek dzēsts.
- N2.14 Dzēšot tiek izdzēsts kontakta ieraksts un tā dalība visās mijiedarbībās (`ON DELETE CASCADE`).
- N2.15 Žurnālā paliek tikai «dzēsts pēc pieprasījuma» un ID. Paziņojums: «Kontaktpersonas dati dzēsti. Žurnālā saglabāts tikai dzēšanas fakts un ID.».

## Ierobežojumi

- Mijiedarbību kopsavilkumos ierakstītais personas vārds pēc dzēšanas paliek (mijiedarbības nevar labot).
- Žurnāls fiksē organizācijas kartītes atvēršanu, nevis katru kontaktu atsevišķi; «kurš redzēja kontaktu X» = kartītes skatījumi, kamēr kontakts pastāvēja.
- Piekļuves un MI žurnāli netiek tīrīti; to glabāšanas termiņš jānosaka datu aizsardzības speciālistam.
- Nav datu eksporta personai (piekļuves tiesības, 15. pants).
